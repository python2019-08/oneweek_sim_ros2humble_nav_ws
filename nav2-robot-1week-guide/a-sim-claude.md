机制：map_server 是 lifecycle node，active 时只发布一次 /map，靠 TRANSIENT_LOCAL 的 latch 能力留给后到的订阅者。RViz 的 Map display 默认是 Volatile，它是在 map_server 发完之后才启动的，而 Volatile 订阅者不接收历史（latch）消息，所以永远收不到 → No map received。TF 里 map 显示 Transform OK 是因为那是 amcl 发的 map→odom，跟 /map 话题无关，别被它误导。

对照证据：Nav2 官方的 rviz 配置里，Map display 就是 Durability Policy: Transient Local（/opt/ros/humble/share/nav2_bringup/rviz/nav2_default_view.rviz:215），而你运行 rviz2 时没带 -d，加载的是 ~/.rviz2/default.rviz，那份是 Volatile。
